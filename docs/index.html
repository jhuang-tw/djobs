Three clear layers

Different state, different authority.

djobs does not turn every prompt into a task and does not pretend memory alone proves completion. Each layer answers a different engineering question.

01

Memory

What already happened?
Query-aware local recall, goals, failures, session capsules, and Git state survive the chat window.

02

Coordination

Who owns this work?
Checkpoint, handoff, leases, and worktree-aware ownership prevent agents from silently duplicating bounded work.

03

Completion

Is it actually done?
Optional ARUN Project Mode owns durable goals, failure/recovery state, scope, evidence coverage, acceptance, and verification.

Optional ARUN Project Mode

Memory tells the next agent where to start. Project state tells it when to stop.

Project Mode is an integration boundary, not a rewrite. djobs keeps memory and coordination. ARUN remains the authoritative durable project state engine and stays executor-neutral.

  • No second LLM, planner, worker, reviewer, or supervisor is started.
  • No ARUN ledgers or promotion gates are copied into djobs.
  • One canonical repository root resolves to one ARUN project.
  • ARUN command failures surface once; the bridge does not hide them with retries.
  • Without ARUN, normal djobs memory continues unchanged.

# create durable project state

  --constraint "No API change" \
  --acceptance "Focused tests pass"

Small MCP surface

Five tools for normal coding sessions.

Keep the common path compact. Project Mode stays explicit instead of bloating every MCP call.

M

sync_workspace + memory

Recover the right context under a token budget, inspect lifecycle state, and retire stale facts without deleting the audit trail.

C

checkpoint + handoff

Claim one bounded unit only when ownership matters, then release or complete it with evidence.

Δ

resume_delta

Compatibility recovery remains available for integrations that already persist queue revisions.

Local and reversible

State stays inspectable.

Memory defaults to ~/.djobs/global.db. Pause stops automatic capture without deleting data. Common credentials are redacted on a best-effort basis, inactive memory can be retired, and storage failures remain fail-open.

01

No hosted account

No cloud database or repository upload is required for normal djobs memory.

02

Memory is data

Recovered text is explicitly untrusted context. The current user request remains authoritative.

03

Opt out and delete

Skip one prompt, pause automatic behavior, retire stale memory, forget one item, or explicitly clear passive memory.
